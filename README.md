# FreeCall

A free 1-to-1 (and small-group) audio/video calling app. Peers talk directly over
WebRTC; the Node.js server only does signaling, so it never sees or pays for a
byte of media.

Three packages, one contract:

| Package  | What it is | Stack |
|----------|------------|-------|
| `server/` | Signaling + REST API | Node.js, Express, Socket.IO, JWT, in-memory stores |
| `web/`    | Browser client | React 18, TypeScript, Tailwind, Vite, WebRTC |
| `mobile/` | Phone client | React Native (Expo), `react-native-webrtc` |

[`CONTRACT.md`](CONTRACT.md) is the single source of truth for every event and
route the three packages share. `shared/types.ts` is the canonical TypeScript
mirror of it, copied verbatim into each package (there is no published npm
package to import, so a checker enforces the copies byte-for-byte — see
[Verifying changes](#verifying-changes)).

## Quick start

Node 18+ and npm 9+ (for workspaces). The launcher does the whole thing —
installs on first run, writes `server/.env`, starts both halves, waits for the
server's `/health` to answer, then opens the browser:

```
start.cmd                    Windows (double-click it, or run it in a terminal)
./start.sh                   macOS / Linux
```

Or by hand, from the repo root:

```bash
npm run install:all          # installs server + web workspaces, then mobile
cp server/.env.example server/.env
npm run dev:server           # → http://localhost:4000
```

In a second terminal:

```bash
npm run dev:web              # → http://localhost:5173
```

Three demo accounts are seeded on every server start — `alice`, `bob` and
`carol`, all with the password `password`. Registration works too; leave the
avatar field blank and you get a generated DiceBear avatar, which is what the
incoming-call screen shows.

### Making a real call

One browser can't call itself, so open a **second browser profile** (or a
private window — the token lives in `localStorage`, so a separate profile is
cleaner) and sign in as a different user. Both users appear in each other's
contact list with a live online dot. Each contact has an audio and a video
button; select several contacts to start a group call, and any entry in the
history tab can be called back with one tap.

Everything works on `localhost` with no extra infrastructure: mute, camera
on/off, hang up, in-call chat, screen sharing, group calls, and call history.

### Production build

```bash
npm run build:server         # tsc → server/dist, run with: npm --workspace server start
npm run build:web            # vite build → web/dist
```

The server does not serve the web app; `web/dist` is a static bundle for any
host you like. Production uses same-origin API and Socket.IO URLs by default. The Cloudflare
Pages gateway forwards them to the configured backend; see [CLOUDFLARE.md](CLOUDFLARE.md).
For a different host without that gateway, set `VITE_SERVER_URL` at build time
and add the web origin to the server's `CLIENT_ORIGINS`. Serve it over HTTPS — browsers won't grant camera or
microphone access to an insecure origin that isn't `localhost`.

## How it fits together

```
  web/  ─┐                      ┌─ Socket.IO ─┐
         ├─ REST /api ──────────┤             ├─→ presence, call setup,
  mobile/─┘                     └─ JWT auth ──┘    SDP/ICE relay, chat

  web/ ←──────────── WebRTC (audio/video/screen) ────────────→ mobile/
                     (peer-to-peer, via STUN/TURN)
```

Two design decisions do most of the work and are worth knowing before you edit
the call code:

**Mesh topology with a deterministic offerer.** Each participant holds one
`RTCPeerConnection` per remote peer. For any pair, the peer whose user id sorts
lexicographically smaller creates the offer; the server computes this per
recipient and ships it as the `initiator` flag on `call:peer-joined`. That's
what keeps offer/offer glare from happening at all instead of being recovered
from. Mesh is why `MAX_PARTICIPANTS` is 6 — upload bandwidth grows with the
number of peers.

**Transceivers are pre-created for audio *and* video, always.** Even an
audio-only call sets up a `sendrecv` video transceiver at connection time. That
makes turning the camera on, flipping it, and starting a screen share pure
`sender.replaceTrack()` calls — no renegotiation, no glare window, no
mid-call SDP churn.

## Configuration

The server reads `server/.env` (see `server/.env.example` for the annotated
version). Everything has a working default except the things that need external
infrastructure.

| Variable | Default | Notes |
|----------|---------|-------|
| `PORT` | `4000` | HTTP + Socket.IO |
| `CLIENT_ORIGINS` | `localhost:5173,localhost:4173` | CORS allowlist. LAN IPs are also allowed in dev. |
| `JWT_SECRET` | `dev-super-secret-change-me` | **Change this** outside dev. |
| `JWT_EXPIRES_IN` | `7d` | |
| `STUN_URLS` | Google + Twilio public STUN | Comma-separated. |
| `TURN_URL` / `TURN_USERNAME` / `TURN_CREDENTIAL` | empty | Needed for strict NATs — see below. |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` | empty | Web push; `npm --workspace server run genkeys` generates a pair. |

The clients need to know where the server is:

- **Web** — `VITE_SERVER_URL`, or nothing at all: it defaults to
  the current origin in production and `http://<current-hostname>:4000` during
  local development. The Cloudflare gateway makes the production origin serve
  both the web app and the backend API.
- **Mobile** — `expo.extra.serverUrl` in `mobile/app.json`. A phone can't reach
  your computer's `localhost`, so this must be your machine's LAN IP.

## Features that depend on external infrastructure

These four work differently (or not at all) until you supply something:

**TURN, for calls that cross strict NATs.** Public STUN is enough for most home
networks and for anything on the same LAN. Symmetric NATs, corporate firewalls
and some mobile carriers will fail to connect without a relay. Set `TURN_URL`
and credentials — a free tier from a hosted provider works, or run
[coturn](https://github.com/coturn/coturn) yourself. `GET /api/config/ice`
hands whatever is configured to both clients.

**Web push needs VAPID keys and a secure context.** Run
`npm --workspace server run genkeys`, paste the pair into `server/.env`, restart.
`GET /api/push/vapidPublicKey` returns `null` when the keys are absent and the
clients degrade quietly rather than erroring. Service workers and
`getUserMedia` also require a secure context, which means `localhost` or HTTPS —
plain `http://192.168.x.x` will not prompt for camera or microphone. To test on
a phone over the LAN, either allow the origin explicitly in Chrome
(`chrome://flags/#unsafely-treat-insecure-origin-as-secure`) or put a tunnel
such as `cloudflared` / `ngrok` in front of the Vite dev server.

**Mobile push needs a real build.** The server delivers to Expo's push service
with a plain HTTPS POST, so no server-side credentials are involved. But
`react-native-webrtc` contains native code, so Expo Go can't run this app at
all — you need `expo run:android` / `expo run:ios` (a dev build), and for
Android delivery an FCM key uploaded to your Expo project. Details in
[`mobile/README.md`](mobile/README.md).

**Screen sharing on mobile is Android-only.** Android has MediaProjection; iOS
requires a Broadcast Upload Extension that `expo prebuild` cannot generate, so
the RN client hides the button there. The web client shares on any desktop
browser via `getDisplayMedia`.

## Verifying changes

`npm run typecheck` runs `tsc` over the server and web workspaces (mobile has
its own: `npm --prefix mobile run typecheck`).

On top of that, `tools/check.py` catches the class of bug that spans packages
and that `tsc` structurally cannot see, because each package compiles in
isolation:

```bash
python3 tools/check.py .
```

It verifies that every relative import resolves and every named import is
really exported, that the three `shared/types.ts` copies are byte-for-byte
identical to the canonical one, that every Socket.IO event name used anywhere
is declared in the shared event interfaces, that every REST path the clients
call exists in the router, and that brackets balance in every `.ts` file. It
also warns about events declared but never emitted, routes missing from
`CONTRACT.md`, and unused imports (an error under `web/`, which builds with
`noUnusedLocals`). Run it before you commit; it's fast and needs no
`node_modules`.

Then there's the behavioural test — 113 assertions that drive the real
signaling server through every call lifecycle in `CONTRACT.md`:

```bash
npm test
```

It imports `server/src/*.ts` unmodified and runs it against a fake Socket.IO,
so it also needs no `node_modules` (see `tools/harness/README.md` for how that
works, and `python3 tools/harness/faults.py` for the mutation testing that
keeps it honest).

## Known limits, on purpose

Storage is **in memory**. Users, calls and history live in `server/src/store.ts`
and vanish when the process restarts — which is the right trade for a demo you
can clone and run in one minute, and a clean seam if you want to swap in a
database later (every read and write goes through that one module).

Group calls are capped at 6 because mesh topology means each participant
uploads a separate stream to every other participant. Going beyond that wants an
SFU, which is a different architecture, not a bigger constant.

A ring times out after 45 seconds. Before anyone answers that ends the call as
missed; afterwards it only retires the invitees who never picked up and leaves
the people already talking connected.

Signing in on several devices rings all of them, and the first one to answer or
decline silences the rest via `call:ended`. The reason strings are in
`CONTRACT.md` under "Ending a ring".
